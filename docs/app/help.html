HazardFill — Help · usage

HF · filling the no-value areas in hazard maps

A procedure to remove unrealistic "islands" of no hazard in a raster hazard map (around buildings, in zones inside the modelled domain, at the edge of the domain). Available as a trial web page and as a QGIS plugin (Processing algorithms); both use the same calculation code and give the same results.

Disclaimer. HazardFill (HF) is a pre-screening aid for land managers in the final assessment of hazard mapping, for a more informed choice and management of the restrictions to be placed on the territory. It does not produce hazard maps, does not replace modelling or expert judgement, and the proposed values are starting examples, not generally valid thresholds.

0. In brief

  1. Prepare the hazard map with classes 0, 1, 2, 3 only (section 1) and, if you have them, the buildings. You can choose the files one by one or a folder: the plugin (menu Raster → HazardFill → Open data folder…) and the web page ("folder" in Load your data) look for rasters and buildings and let you choose which ones to work on.
  2. Choose the steps to apply: buildings, interior zones, buffer. The proposed values are starting examples, not definitive parameters.
  3. See where the map has changed (modified pixels have their own code) and adjust the parameters.
  4. Export the raster (with codes or clean) and the map image with legend, north arrow and scale.

1. Input data

Hazard map (raster)

  • GeoTIFF (or another GDAL format) with one band, regular "north-up" grid, in a projected coordinate system in metres (e.g. EPSG:32632). A geographic CRS (degrees) is not accepted.
  • Allowed values, only these classes:
    ValueMeaning
    0no hazard / outside the domain / nodata
    1low hazard
    2medium hazard
    3high hazard
  • Nodata (also negative values such as −9999, NaN, etc.) is treated as 0. Non-integer values are rounded; values >3 are capped at 3. If your map uses other codes, reclassify it first (Raster → Raster calculator).
  • The original file is never modified: results are always written to new files.

Buildings (polygon vector, optional if OSM is used)

  • Any format (shapefile, GeoPackage, ...), polygon geometries, any CRS (reprojected to the raster CRS). No attributes needed.
  • Buildings were not present in the simulation (treated as obstacles/removed): this is why the hazard on buildings is reconstructed from the surrounding pixels (criterion 0).

Buildings from OpenStreetMap (option)

  • Source provided buildings only (default) / provided + add from OSM / OSM only.
  • Buildings are downloaded from OpenStreetMap (Overpass service) for the raster extent; an internet connection is required. Out of respect for the service, results are cached on disk and requests automatically retry on alternative servers when they are busy.
  • With add, an OSM building is added only if less than 20% of its area falls on buildings you already provided, so buildings present in your data are not duplicated.
  • If the OSM service is slow or does not answer (it happens), the operation can be cancelled and it is better to provide the buildings as a shapefile (also .zip) or GeoPackage: the repository contains a ready example (examples/Spona_test).
  • Limits: OSM coverage varies from place to place; of multipolygons only the outer rings are used (inner courtyards are ignored). Data © OpenStreetMap contributors (ODbL): credit the source.

2. Criteria, with examples

In the examples each square is a pixel and the number is its value. Blue outline = building. Hatched pixels are those modified by the step and show their code (see section 3). Steps are applied in the order 0 → 1 → 2.

0. Buildings

Each building takes the maximum hazard value that touches it or lies within the tolerance (in metres) from its edge. An existing value is never lowered.

Parameter: tolerance from the edge in metres (default 0 m). With 0 only the hazard inside the building counts; with values >0 also that in the surrounding band. Metres are converted to pixels with the raster resolution (rounding): at 0.5 m/pixel, 1 m = 2 pixels.

1. Closing interior zones

Zones at 0 that are "interior" to the modelled domain (islands of no hazard surrounded by values >0, not connected to the raster edge) are filled if their area is ≤ A m², or all of them (option "close ALL").

How interior/exterior is decided: the "wide" parts of each zone at 0 are found (farther than half the gap from a valid value); those touching the raster edge are "exterior"; every pixel at 0 is assigned to the nearest wide zone by walking only over 0s. Pixels not reached from the outside are "interior".

1b. Sealable gap

With a gap of 0 m only completely enclosed zones are interior. With a gap >0, zones connected to the outside only through passages narrower than the gap are also considered interior (pockets with a small opening, for example a zone closed by an embankment with a single break). All scales up to the given gap are considered.

1c. Fill value

Which value the closed interior zones receive:

  • most frequent boundary value or majority (major, default): the value with the most boundary cells;
  • boundary maximum (max): the highest of the values surrounding the zone (a cautious choice);
  • nearest (near): each cell takes the value of the nearest valid cell (useful for large zones with varied boundary).

2. Graded buffer on class 0

A band of given width in metres (default 1 m) on class 0 adjacent to valid pixels receives the value of the nearest valid pixel minus 1 degree (minimum 1). It never overwrites pixels that are already valid. It is useful where the model ends "in the void" (edge of the domain).

A pixel modified by one step is not reassigned by the following ones: the code records the first step that modified it.

Vector (GeoPackage)Polygons with the same codes as the raster, in 4 layers: originale (classes 1-3 of the starting map), omogeneizzata (classes 1-3 after filling), mappa_con_codici (all codes 1-3, 11-33) and modifiche (only the modified polygons, codes 11-33). Map image (PNG)Map with title, legend, north arrow and scale, at 150 dpi (section 4).

The vector is obtained by polygonizing the pixels (adjacent cells of the same value merged, 4-connected, with stepped edges): geometries are valid and, by construction, have no overlaps or gaps between polygons; the sum of the areas of each code equals that of the raster pixels. Web page: "Vector (GeoPackage) with codes" button; plugin: optional output "GeoPackage vector with codes". For very large rasters generation can take minutes.

How it looks. In the raster with codes the values are shown as single classes (not blended), from yellow (1) to orange (2) to red (3): classes ending in 3 are the most severe. Modified pixels have the same hue but darker, different for each criterion. Where possible (vector, web page, images) modified pixels also have a hatch that depends on the criterion: buildings with oblique lines, interior zones with horizontal lines, buffer with vertical lines. By default the plugin algorithm creates a single raster (with codes); the clean raster (only 0-3) is obtained by ticking the corresponding box.

Codes in the "with codes" raster: tens = step that modified the pixel, units = assigned hazard level.

CodeMeaning
0nodata / no hazard
1 2 3original (unmodified) hazard low / medium / high
11 12 13value 1/2/3 assigned by buildings
21 22 23value 1/2/3 assigned by interior zones
31 32 33value 1/2/3 assigned by graded buffer

Example: 23 = high-hazard pixel (3) assigned by an interior zone (2). The parameters used are written in the GeoTIFF metadata (Properties → Information).

4. Map image (legend, north, scale)

  • Web page: section "Export map (image)". Choose as on screen, original map only or map with fills only; the PNG shows what you see (basemap, hillshade, layers, buildings).
  • Plugin: algorithm "Export map with legend, north and scale (PNG)": it uses the visible layers of the QGIS project, the extent you indicate and the processed (or original) raster to describe in the legend.
  • Title: if there are fills, a sentence (e.g. "with fills at buildings and zones inside the mapping") and the parameters used appear under the title; without fills there is only the title.
  • The legend shows classes 1-3 and the codes (11-13, 21-23, 31-33) of the selected steps only.
  • Scale: minimum length 100 m, unit written once at the end. Output at 150 dpi.
  • The default file name contains the word fills (riempimenti) when fills are active.

5. Usage notes

  • Start with the example values (buildings 0 m, interior zones 10 m², buffer 1 m, fill by majority) and look at where changes occurred (codes ≥11).
  • The values used are examples to help the choice, not definitive parameters: the final choice belongs to the decision maker, based on the comparison between the original map and the map with fills.
  • For large interior zones noted in the results, increase the area or use "close ALL" and/or the gap: check visually that water arms or stretches truly without hazard are not closed.
  • The buffer only makes sense where the model ends "in the void"; large values widen the map beyond what was simulated.
  • Always keep the raster with codes: it lets you tell simulated data from assigned data at any time.
  • Building tolerance, buffer and gap (metres) and area (m²) are converted to pixels with the raster resolution.

6. Memory and run times

The calculation works in memory on the whole raster (numpy/scipy). For very large rasters (tens of millions of pixels, e.g. 0.5 m over several km²) a few GB of RAM and from seconds to minutes are needed; closing interior zones with a large gap is the heaviest step.

HazardFill — Help · utilizzo

HF · chiusura delle aree prive di valore nelle mappe di pericolosità

Procedura per rimuovere le "isole" di assenza di pericolo non realistiche in una mappa di pericolosità raster (attorno agli edifici, in zone interne al dominio modellato, al margine del dominio). Disponibile come pagina web di prova e come plugin QGIS (algoritmi di Processing); i due usano lo stesso codice di calcolo e danno gli stessi risultati.

Avvertenza. HazardFill (HF) è un ausilio di pre-screening per i gestori del territorio nella fase di valutazione finale della mappatura del pericolo, per una scelta e una gestione più consapevoli del vincolo da apporre sul territorio. Non produce mappe di pericolosità, non sostituisce la modellazione né la valutazione di esperti, e i valori proposti sono esempi di partenza, non soglie di validità generale.

0. In breve

  1. Prepara la mappa di pericolosità con solo le classi 0, 1, 2, 3 (sezione 1) e, se li hai, gli edifici. Puoi scegliere i file uno per uno oppure una cartella: il plugin (menu Raster → HazardFill → Apri cartella di dati…) e la pagina web («cartella» in Carica i tuoi dati) cercano raster ed edifici e ti fanno scegliere su quali lavorare.
  2. Scegli i passi da applicare: edifici, zone interne, buffer. I valori proposti sono esempi di partenza, non parametri definitivi.
  3. Guarda dove la mappa è cambiata (i pixel modificati hanno un codice proprio) e regola i parametri.
  4. Esporta il raster (con codici o pulito) e l'immagine della mappa con legenda, nord e scala.

1. Dati in ingresso

Mappa di pericolosità (raster)

  • GeoTIFF (o altro formato GDAL) a una banda, griglia regolare "nord in alto", in un sistema di coordinate proiettato in metri (es. EPSG:32632). Un CRS geografico (gradi) non è accettato.
  • Valori ammessi, solo queste classi:
    ValoreSignificato
    0nessun pericolo / fuori dal dominio / nodata
    1pericolo basso
    2pericolo medio
    3pericolo alto
  • Il nodata (anche valori negativi come −9999, NaN, ecc.) viene assimilato a 0. Valori non interi vengono arrotondati; valori >3 limitati a 3. Se la tua mappa usa altri codici, riclassificala prima (Raster → Calcolatore raster).
  • Il file originale non viene mai modificato: i risultati sono sempre scritti in nuovi file.

Edifici (vettore poligonale, opzionale se si usa OSM)

  • Qualsiasi formato (shapefile, GeoPackage, ...), geometrie poligonali, qualsiasi CRS (viene riproiettato nel CRS del raster). Non servono attributi.
  • Gli edifici non erano presenti nella simulazione (considerati ostacoli/rimossi): per questo il pericolo sugli edifici viene ricostruito dai pixel circostanti (criterio 0).

Edifici da OpenStreetMap (opzione)

  • Sorgente solo edifici forniti (predefinito) / forniti + integra da OSM / solo OSM.
  • Gli edifici vengono scaricati da OpenStreetMap (servizio Overpass) per l'estensione del raster, serve connessione internet. Per rispetto del servizio i risultati sono messi in cache su disco e le richieste ritentano automaticamente su server alternativi se sono occupati.
  • Con integra, un edificio OSM viene aggiunto solo se meno del 20% della sua superficie ricade su edifici già forniti, così non si duplicano gli edifici presenti nei tuoi dati.
  • Se il servizio OSM è lento o non risponde (capita), l'operazione si può annullare e conviene fornire gli edifici come shapefile (anche .zip) o GeoPackage: nel repository c'è un esempio pronto (examples/Spona_test).
  • Limiti: la copertura OSM varia da zona a zona; dei multipoligoni sono usati solo gli anelli esterni (i cortili interni sono ignorati). Dati © contributori OpenStreetMap (ODbL): citare la fonte.

2. Criteri, con esempi

Negli esempi ogni quadratino è un pixel e il numero è il valore. Bordo azzurro = edificio. I pixel tratteggiati sono quelli modificati dal passo e riportano il loro codice (vedi sezione 3). I passi vengono applicati nell'ordine 0 → 1 → 2.

0. Edifici

Ogni edificio assume il valore di pericolo massimo che lo tocca o che si trova entro la tolleranza (in metri) dal suo bordo. Un valore esistente non viene mai abbassato.

Parametro: tolleranza dal bordo in metri (predefinito 0 m). Con 0 conta solo il pericolo dentro l'edificio; con valori >0 anche quello nella fascia attorno. I metri sono convertiti in pixel con la risoluzione del raster (arrotondando): a 0,5 m/pixel, 1 m = 2 pixel.

1. Chiusura zone interne

Le zone a 0 "interne" al dominio modellato (isole di assenza di pericolo circondate da valori >0, non collegate al margine del raster) vengono riempite se la loro area è ≤ A m², oppure tutte (opzione "chiudi TUTTE").

Come si decide interno/esterno: si cercano le parti "larghe" di zona a 0 (più lontane dal valore valido di metà varco); quelle che toccano il bordo del raster sono "esterno"; ogni pixel a 0 viene assegnato alla zona larga più vicina camminando solo sugli 0. I pixel non raggiunti dall'esterno sono "interni".

1b. Varco sigillabile

Con varco 0 m sono interne solo le zone completamente chiuse. Con un varco >0 sono considerate interne anche le zone collegate all'esterno solo da passaggi più stretti del varco (tasche con apertura piccola, ad esempio una zona chiusa da un argine con una sola interruzione). Si considerano tutte le scale fino al varco indicato.

1c. Valore di riempimento

Quale valore ricevono le zone interne chiuse:

  • più frequente del contorno o maggioranza (major, predefinito): il valore con più celle di contorno;
  • massimo del contorno (max): il più alto tra i valori che circondano la zona (scelta prudente);
  • più vicino (near): ogni cella prende il valore della cella valida più vicina (utile per zone grandi con contorno vario).

2. Buffer graduato sulla classe 0

Una fascia di larghezza data in metri (predefinito 1 m) sulla classe 0 adiacente a pixel validi riceve il valore del pixel valido più vicino meno 1 grado (minimo 1). Non sovrascrive mai pixel già validi. Serve dove il modello termina "nel vuoto" (margine del dominio).

Un pixel modificato da un passo non viene riassegnato dai successivi: il codice registra il primo passo che l'ha modificato.

Il vettoriale si ottiene per poligonizzazione dei pixel (celle adiacenti dello stesso valore unite, 4-connesse, con bordi a gradini): le geometrie sono valide e, per costruzione, senza sovrapposizioni né vuoti tra poligoni; la somma delle aree di ogni codice coincide con quella dei pixel del raster. Pagina web: pulsante «Vettoriale (GeoPackage) con codici»; plugin: uscita facoltativa «Vettoriale GeoPackage con codici». Per raster molto grandi la generazione può richiedere minuti.

Come si vede. Nel raster con codici i valori sono mostrati a classi singole (non sfumati), dal giallo (1) all'arancio (2) al rosso (3): le classi che finiscono con 3 sono le più gravose. I pixel modificati hanno la stessa tonalità più scura, diversa per criterio. Dove si può (vettoriale, pagina web, immagini) i pixel modificati hanno anche un retino che dipende dal criterio: edifici a linee oblique, zone interne a linee orizzontali, buffer a linee verticali. L'algoritmo del plugin crea di default un solo raster (con codici); il raster pulito (solo 0-3) si ottiene spuntando la casella apposita.

Codici nel raster "con codici": decine = passo che ha modificato il pixel, unità = livello di pericolo assegnato.

CodiceSignificato

1 2 3pericolo originale (non modificato) basso / medio / alto
11 12 13valore 1/2/3 assegnato da edifici
21 22 23valore 1/2/3 assegnato da zone interne

Esempio: 23 = pixel di pericolo alto (3) assegnato da una zona interna (2). I parametri usati sono scritti nei metadati del GeoTIFF (Proprietà → Informazioni).

4. Immagine della mappa (legenda, nord, scala)

  • Pagina web: sezione "Esporta mappa (immagine)". Si sceglie come a schermo, solo mappa originale o solo mappa con riempimenti; il PNG riporta quello che vedi (base cartografica, hillshade, layer, edifici).
  • Plugin: algoritmo "Esporta mappa con legenda, nord e scala (PNG)": usa i layer visibili del progetto QGIS, l'estensione che indichi e il raster elaborato (o originale) da descrivere in legenda.
  • Titolo: se ci sono riempimenti compaiono sotto il titolo una frase (es. "con riempimenti in corrispondenza di edifici e zone interne alla mappatura") e i parametri usati; senza riempimenti c'è solo il titolo.
  • La legenda riporta le classi 1-3 e i codici (11-13, 21-23, 31-33) solo dei passi selezionati.
  • Scala: lunghezza minima 100 m, unità scritta una sola volta in fondo. Uscita a 150 dpi.
  • Il nome file di default contiene la parola riempimenti quando i riempimenti sono attivi.

5. Indicazioni d'uso

  • Parti con i valori di esempio (edifici 0 m, zone interne 10 m², buffer 1 m, riempimento per maggioranza) e guarda dove sono avvenute le modifiche (codici ≥11).
  • I valori usati sono esempi per aiutare la scelta, non parametri definitivi: la scelta finale spetta al decisore, sulla base del confronto tra mappa originale e mappa con riempimenti.
  • Per zone interne grandi note nei risultati aumenta l'area o usa "chiudi TUTTE" e/o il varco: controlla visivamente che non vengano chiusi bracci d'acqua o tratti realmente privi di pericolo.
  • Il buffer ha senso solo dove il modello termina "nel vuoto"; valori elevati allargano la mappa oltre quanto simulato.
  • Mantieni sempre il raster con i codici: permette di distinguere in ogni momento dato simulato e dato assegnato.
  • Tolleranza edifici, buffer e varco (metri) e area (m²) sono convertiti in pixel con la risoluzione del raster.

6. Memoria e tempi

Il calcolo lavora in memoria su tutto il raster (numpy/scipy). Per raster molto grandi (decine di milioni di pixel, es. 0,5 m su più km²) servono alcuni GB di RAM e da secondi a minuti; la chiusura delle zone interne con varco grande è il passo più pesante.
